# PaperExtractor 项目完整说明

> 用途：可直接发送给 Claude、导师或同学，让对方快速理解项目的目标、完整实现、真实结果与边界。

## 1. 项目是什么？

**PaperExtractor** 是一个面向学术论文的批量信息抽取系统。用户上传 PDF 或 DOCX 后，系统解析全文并调用 OpenAI 兼容的大模型（本项目实际接入 DeepSeek），输出结构化论文信息，保存到数据库，并导出 Excel/JSON。

它解决的不是“让模型总结一篇论文”这么简单，而是将批量文献整理变成一条可运行、可追踪、可失败隔离、可导出、可通过 Web 使用、可量化评测的工程流水线。

## 2. 输入、输出与 11 个字段

输入：电子版 PDF 或 DOCX 论文。

输出：每篇论文统一抽取 11 个字段：

1. `title`：标题
2. `authors`：作者列表
3. `year`：年份
4. `venue`：期刊、会议或预印本平台
5. `doc_type`：文档类型
6. `problem`：研究问题
7. `method_name`：方法名称
8. `experimental_conditions`：实验条件
9. `main_results`：主要结果
10. `limitations`：作者明确陈述的局限性
11. `summary`：摘要式总结

对于光通信论文，`experimental_conditions` 用于记录 PAM/QAM 调制格式、波特率、波长、传输距离、光纤类型、功率、误码率门限等明确实验事实。论文没有明确写出的条件不猜测；局限性也不允许模型自行推断。

## 3. 完整模块与流程

```text
PDF / DOCX
  → M1 文档解析（逐页文本）
  → M2 LLM 客户端与 Prompt
  → M3 JSON 清洗 + Pydantic 校验 + 三级容错
  → M4 线程池批量调度与进度回调
  → M5 SQLite 持久化
  → M6 Excel / JSON 导出
  → M7 FastAPI 接口
  → M8 Streamlit 可视化界面
  → M9 冻结测试集上的字段级评测
```

### M1：文档解析

- 使用 `pdfplumber` 解析 PDF，使用 `python-docx` 解析 DOCX。
- 返回页数、全文、逐页文本和文件元数据。
- 对加密、损坏、扫描型或格式不支持的文档给出明确错误，不将其误当作大模型失败。

### M2：LLM 客户端与 Prompt

- 使用 `httpx` 调用 OpenAI 兼容接口，当前配置为 DeepSeek。
- 支持超时、429/5xx/网络错误的指数退避重试。
- 关闭不必要的 thinking，启用 JSON 输出模式，降低结构化抽取的 token 消耗与格式噪声。

### M3：三级容错抽取器

三级容错指：

1. 解析模型返回 JSON；
2. 用 Pydantic 校验 11 个字段的类型、枚举、长度和业务规则；
3. 如果 JSON 或字段不合法，把具体错误反馈给模型，要求只修正并重新输出。

重试耗尽时不会中断整批任务，而会生成带有失败阶段、错误类型、原始输出和重试记录的失败对象。

### M4：批量调度

- 使用 `ThreadPoolExecutor` 并发处理 I/O 密集型 PDF 解析和 API 调用。
- 默认并发可由 `.env` 配置。
- 每篇完成时通过进度回调通知控制台/API/UI；单篇失败不影响其他论文。

### M5：SQLite 持久化

- 用 SQLite 保存任务、成功结果和失败诊断三类数据。
- 使用事务与外键保证任务和明细一致。
- 选择 SQLite 而不是 MySQL/PostgreSQL，是因为当前定位为本地单用户工具，不需要部署额外数据库服务。

### M6：Excel / JSON 导出

- 按 `task_id` 导出，避免重新调用模型。
- Excel 包含论文结果、失败记录、任务概览三个工作表，支持筛选、冻结首行和自适应列宽。
- 对以 `= + - @` 开头的外部文本进行公式注入防护。

### M7：FastAPI

- 提供文件上传、创建任务、查询任务、下载 Excel/JSON 的 HTTP 接口。
- FastAPI 根据 Pydantic 模型生成 Swagger `/docs` 页面。
- Uvicorn 负责监听本地端口并承载 FastAPI 应用。

### M8：Streamlit

- 提供无需手写前端代码的本地网页界面。
- 支持多文件上传、任务历史、失败诊断、结果预览和导出下载。
- Streamlit 是界面层；真正的业务处理仍由 FastAPI 与 M1-M6 执行。

### M9：准确率评测

- 区分“模型可用性”与“字段语义正确性”。
- `year`、`doc_type` 用精确匹配；标题、方法、期刊用归一化模糊匹配；作者、实验条件、主要结果用集合 F1 或原子事实 F1。
- `problem`、`limitations`、`summary` 是自由文本，不做不可靠的自动字符串评分，保留人工抽检。

## 4. 真实评测设计与结果

### 数据集如何保证可信？

- 固定 30 篇公开光通信论文作为最终留出集。
- 每篇下载到本地后进行 SHA-256 校验。
- 外部 AI（Gemini）只能提供初标草稿，初标始终是 `needs_review=true`。
- 再对照本地真实 PDF 全文核验标题、作者、实验条件和数值事实。
- 发现并修正了实际错误：例如 F02 的距离从错误的 10-25 km 改为原文的 4-8 km；F22/F25 补全作者；F25 修正标题与实验事实。
- 全部 30 篇通过全文审计后，才冻结为 `needs_review=false` 的评测标准答案。

### 最终结果

在 30 篇冻结留出论文、`deepseek-v4-flash`、温度 0.0 的真实两轮运行中：

| 指标 | 无内容修正重试 | 三级容错 | 变化 |
| --- | ---: | ---: | ---: |
| 成功抽取论文 | 27/30（90.00%） | 30/30（100.00%） | +10.00pp |
| 8 个自动字段宏平均 | 45.79% | 50.47% | +4.68pp |
| 标题 | 90.00% | 100.00% | +10.00pp |
| 作者 F1 | 82.72% | 89.81% | +7.08pp |
| 实验条件 F1 | 34.40% | 43.74% | +9.34pp |
| 主要结果 F1 | 42.52% | 50.18% | +7.66pp |

三篇 F21、F26、F28 在对照组因 Schema 校验失败无法进入下游；三级容错将三篇全部修复为合法结构化输出。因此，**27/30 到 30/30 的可用性提升**是本项目最直接、最可信的工程成果。

## 5. 项目亮点

1. **不是只会调用 LLM，而是有完整工程链路**：文档解析、容错、批处理、数据库、导出、API、界面、评测都打通。
2. **结构化输出有严格边界**：JSON 合法不等于业务正确，Pydantic 同时约束格式和业务规则。
3. **单篇失败隔离**：一份坏 PDF 或一次 API 异常不会毁掉整批任务。
4. **可追踪性**：保存重试次数、错误阶段、token、耗时和原始失败信息。
5. **面向真实使用的导出**：Excel 面向人工筛选，JSON 面向程序对接，且有公式注入防护。
6. **Web 化交付**：FastAPI 提供标准后端接口，Streamlit 提供可用的演示界面。
7. **评测比“看着像对”更严格**：建立冻结留出集、人工/PDF 核验、字段级指标、两轮对照和报告。
8. **遵守实验边界**：最终留出集一旦用于最终分数，就不再用它继续调 Prompt 或规则，避免测试集泄漏。
9. **有负结果也保留**：V3-V6/B2 等尝试并非都带来泛化提升，项目保留了失败实验和原因，而不是只展示好看的结果。

## 6. 已做的改进与结论

### 有效改进

- M3 的 JSON/Pydantic 修正重试：使最终留出集成功率从 90% 提升到 100%。
- 增加明确字段错误反馈：把“模型输出了 JSON 但字段不合格”转化为可修复的请求。
- 对实验条件和主要结果采用原子事实 F1：减少不同分句方式造成的误判。
- 外部 AI 标注导入器 + 本地 PDF 审计 + 硬性确认门槛：防止 AI 草稿直接污染最终评测答案。
- 最终预测增加逐篇检查点：长批次网络中断后可从已落盘结果恢复，避免重复调用和费用浪费。

### 未推广或未泛化的尝试

- 结构化对象输出 B2 试点：虽然 10/10 成功，但实验条件和主要结果 F1 没有提升，因此未替换主流程。
- V3-V6 的 Prompt/证据策略：在小开发集上有局部改善，但在已冻结盲测上没有稳定泛化，因此保留为实验记录，不作为默认方案。

## 7. 当前不足与下一步方向

1. **方法名称准确率低（3.33%）**：名称可能分散在图注、正文、缩写和组合方法描述中；仅凭通用全文截断难以稳定定位。
2. **期刊/会议字段低（20%）**：预印本、会议版本、期刊版本之间存在文献口径差异，需要先明确评价口径或接入可靠元数据源。
3. **实验条件/主要结果仍有召回不足**：长论文中事实分散，模型可能漏掉多个关键数值。后续可在全新评测集上研究分段检索、字段专用证据窗口或引用原文页码。
4. **未支持 OCR**：扫描版 PDF 目前会被明确拒绝；若未来要支持，需要新增 OCR 阶段并重新评估误差传播。
5. **单机本地部署**：SQLite、Streamlit、Uvicorn 适合演示与个人使用；多人高并发场景需迁移到生产数据库、对象存储、队列和独立前端部署。

> 重要边界：当前最终 30 篇留出集已经使用完成，不能再据此继续调 Prompt、规则或阈值。后续任何优化都必须建立新的独立数据集验证。

## 8. 如何演示

### 推荐演示：网页端

1. 在 VS Code 打开项目根目录。
2. 点击左侧“运行和调试”。
3. 选择 `M8：同时启动后端与界面`，点击绿色运行按钮。
4. 浏览器打开 `http://127.0.0.1:8501`。
5. 上传 1-3 篇 PDF，提交任务。
6. 查看论文结构化结果、失败诊断，并下载 Excel/JSON。

### 推荐讲解顺序

```text
上传 PDF
→ FastAPI 接收任务
→ M1 解析文本
→ DeepSeek 抽取 11 字段
→ M3 校验与修正失败输出
→ SQLite 保存
→ Streamlit 查看与下载 Excel / JSON
→ M9 用冻结集验证工程收益
```
