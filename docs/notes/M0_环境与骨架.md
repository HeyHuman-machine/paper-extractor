# M0：环境与项目骨架讲解稿

## 这个模块解决什么问题

写程序之前，先要保证每个人使用的是同一种 Python 和同一组第三方库。
否则很容易出现“在我的电脑上能运行，换一台电脑就报错”的问题。

M0 做了三件事：

1. 用 `uv` 准备 Python 3.11。
2. 用 `.venv` 把本项目的依赖与电脑上的其他项目隔离开。
3. 建好目录、配置文件和 Git 基线，让后续模块有固定位置可放。

这个模块的输入是 Windows 电脑和项目规格书；输出是一个可以独立运行
`hello.py` 的 Python 3.11 项目环境。

## 数据怎么进来、怎么出去

M0 还没有论文数据。

- 输入：操作系统信息、Python 版本要求和依赖清单。
- 处理：`uv` 读取 `pyproject.toml`，创建 `.venv` 并安装依赖。
- 输出：虚拟环境、`uv.lock` 锁文件，以及环境检查脚本的成功信息。

执行：

```powershell
uv sync
uv run python hello.py
```

看到下面的文字就说明环境正确：

```text
PaperExtractor 环境准备完成
Python version: 3.11.x
```

## 主要文件分别做什么

### `pyproject.toml`

它相当于项目的“依赖说明书”，记录项目名称、Python 版本范围和允许安装的
第三方库。别人拿到项目后运行 `uv sync`，就能获得一致的环境。

### `uv.lock`

`pyproject.toml` 写的是允许范围，`uv.lock` 记录最终解析出的精确版本。
这样可以降低今天能运行、以后因为依赖升级而不能运行的风险。

### `.venv`

这是项目的虚拟环境。可以把它理解成项目自己的 Python 工具箱。它不会修改
系统原有的 Python 3.12，也不会与其他项目安装的库混在一起。

### `.env.example`

这是环境变量模板，只展示需要哪些配置，不包含真实 API Key。以后用户会复制
为 `.env` 并填写真实值，而 `.env` 已被 Git 忽略，避免密钥泄漏。

### `.gitignore`

它告诉 Git 哪些文件不能提交，例如虚拟环境、真实密钥、数据库、日志和用户
上传的论文。

### `hello.py`

这是 M0 的独立验收入口，只检查当前解释器是不是 Python 3.11，并打印系统
信息。它不依赖后续业务模块，所以今天就能看到结果。

## `hello.py` 中的 Python 语法

### `import`

```python
import platform
import sys
```

`import` 和 Java 的 `import` 概念相近。`platform` 和 `sys` 都是 Python 标准库，
不需要额外安装。

### 函数定义和类型提示

```python
def main() -> int:
```

`def` 用于定义函数。`-> int` 表示该函数预计返回整数，它主要帮助阅读和工具
检查，并不会像 Java 那样在运行时强制类型。

### 元组

```python
required_version = (3, 11)
```

圆括号中的 `(3, 11)` 是元组，可以理解为一个不能随意修改的小型有序集合。
这里用它表示主版本号和次版本号。

### 条件判断

```python
if current_version != required_version:
```

Python 用缩进表示代码块，不使用 Java 的花括号。`!=` 表示“不等于”。

### f-string

```python
f"Python version: {platform.python_version()}"
```

字符串前面的 `f` 表示可以把花括号里的表达式结果放进字符串。

### 程序入口

```python
if __name__ == "__main__":
    raise SystemExit(main())
```

直接运行文件时，Python 会把 `__name__` 设置成 `"__main__"`。这个判断保证
`main()` 只在直接运行时执行，被其他文件导入时不会自动执行。

## 为什么选择 uv

传统方案是手工安装 Python，再用 `venv + pip + requirements.txt` 管理依赖。
它可以工作，但步骤更多，而且依赖锁定需要额外操作。`uv` 能统一管理 Python、
虚拟环境、依赖安装和锁文件，更适合14天内需要反复演示的项目。

没有直接使用电脑现有的 Python 3.12，是因为规格明确要求 Python 3.11。
把版本固定下来能减少面试演示当天出现兼容性差异的风险。

## 面试官可能会问的问题

### 1. 为什么要使用虚拟环境？

参考答案：不同项目依赖的库版本可能不同。虚拟环境把每个项目的 Python 和
第三方库隔离开，避免升级一个项目的依赖时破坏另一个项目，也方便在其他电脑
复现环境。

### 2. `pyproject.toml` 和 `uv.lock` 有什么区别？

参考答案：`pyproject.toml` 描述项目需要哪些依赖及允许的版本范围，
`uv.lock` 记录解析后实际使用的精确版本。前者表达需求，后者保证复现。

### 3. 为什么不直接使用系统里的 Python 3.12？

参考答案：项目规格固定为 Python 3.11。明确版本可以降低依赖兼容差异，保证
开发、测试和面试演示使用同一环境。`uv` 管理的 3.11 与系统 3.12 可以并存，
不会相互覆盖。
