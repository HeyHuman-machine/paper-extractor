# M6：Excel 与 JSON 导出

## 这一阶段解决什么

M5 已经把批次结果保存在 SQLite 中，但数据库更适合程序查询，不适合直接交给人阅读。M6 使用 `task_id` 找回同一批数据，并生成两种用途不同的文件：

- Excel：给人查看、筛选和横向比较论文。
- JSON：给程序、API 或后续系统继续处理。

## 文件怎样协作

```text
task_id
  ↓
app/exporter.py
  ↓ 调用
app/db.py ──查询──> tasks + results + failures
  ↓
论文对比表.xlsx + 完整结构化数据.json
```

`exporter.py` 不重新解析 PDF，也不重新调用 LLM。它只消费 M5 已经验证并保存的数据，所以导出不会产生 API 费用。

## 两个核心函数

```python
export_excel(task_id, path, db_path=...)
export_json(task_id, path, db_path=...)
```

- `task_id`：要导出哪一次批处理。
- `path`：文件保存到哪里。
- `db_path`：数据库在哪里；正式运行可省略，测试时传入临时数据库。
- 返回值：最终生成文件的 `Path`。

## Excel 的设计

- `论文结果`：每一行是一篇成功论文，包含文件名、11 个目标字段和运行指标。
- 光通信论文使用 `experimental_conditions`（实验条件）代替通用的 `datasets`，记录调制格式、波特率、载波频率、传输距离、功率和采样率等论文明确给出的条件。
- `limitations` 只接受作者明确陈述的限制；论文未写时保持空值，不用推测性语句填满表格。
- `失败记录`：解析或抽取失败的文件单独保存，不污染成功对比表。
- `任务概览`：展示 `tasks` 表的一条批次总览，包括总数、成功数、失败数、token 和耗时。
- 表头加粗并冻结首行；滚动后仍能知道每一列是什么。
- 开启筛选，列表字段用单元格内换行展示。
- 列宽根据内容调整并设置上限，避免一段长摘要把表格无限拉宽。

## JSON 的设计

顶层分为：

```json
{
  "task": {},
  "results": [],
  "failures": []
}
```

JSON 保留列表类型和完整数据库字段，适合 M7 FastAPI 直接返回或其他程序继续读取。

## 日常操作

`.env` 使用 `INPUT_DIR` 和 `OUTPUT_DIR` 集中管理路径。`run_real_m1_m6.py`
会自动扫描输入目录第一层的全部 PDF / DOCX，不再维护固定文件名列表。修改目录时
只改 `.env`，无需进入 Python 程序。
