# M8：Streamlit 可视化界面

## M7 到 M8 的进步

M7 已经把 M1～M6 包装成 HTTP 接口，但 Swagger 主要给开发者调试。M8 增加正式操作界面，让使用者不需要填写 URL、请求参数或阅读 JSON。

```text
使用者 → Streamlit 页面 → HTTP 请求 → M7 FastAPI → M1～M6 → SQLite
                       ← 任务、结果、导出文件 ←
```

用 Java Web 类比：M7 接近 Spring MVC 后端，M8 接近面向用户的管理页面。Streamlit 同时负责页面组件和与 Python 交互，但业务规则仍放在 M1～M7，不复制到界面中。

## 四个页面

| 页面 | 能做什么 | 是否调用 DeepSeek |
|---|---|---|
| 新建任务 | 多选 PDF / DOCX、开始处理、查看结果、下载文件 | 点击“开始处理”后会调用 |
| 历史任务 | 查看 task_id、成功率、耗时和完整字段 | 否 |
| 失败诊断 | 查看失败阶段、错误类型、信息与原始输出 | 否 |
| 评测 | M9 标注进度、两轮准确率与对比图 | 否 |

## 新建任务流程

1. 浏览器先把所选文件放进待处理列表，此时没有上传、不会调用模型。
2. 点击“开始处理”，M8 用 `multipart/form-data` 把文件发给 `POST /api/tasks`。
3. M7 同步运行 M1～M6；M8 显示处理中状态。
4. 数据入库后 M7 返回 `task.id`、成功结果与失败统计。
5. M8 把 JSON 转成任务指标、论文表格和完整字段，不改变数据内容。
6. 下载按钮请求 M7 的导出接口，复用 M6 生成 Excel / JSON。

> 当前 M7 是同步接口，所以 M8 能明确显示“上传中 / 后端处理中 / 完成”，但不能取得每篇论文的实时百分比。若以后需要逐文件实时进度，应把 M7 改为后台任务，再提供状态查询或 WebSocket / SSE。

## 关键文件

- `ui/streamlit_app.py`：页面、导航、状态和用户交互。
- `ui/api_client.py`：集中调用 M7，不让页面散落 HTTP 细节。
- `ui/view_models.py`：把 API JSON 转成适合表格显示的中文列。
- `.streamlit/config.toml`：冷色主题、上传大小与工具栏设置。
- `.vscode/launch.json`：单独启动 M7/M8，或一次同时启动两者。

## 怎样运行

最简单方式是在 VS Code“运行和调试”选择：

```text
M8：同时启动后端与界面
```

浏览器访问 <http://127.0.0.1:8501>。绿色的“M7 API 已连接”表示前端能够访问后端；红色未连接时，应先检查 8000 端口上的 M7。
